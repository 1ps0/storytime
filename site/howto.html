Install

# Permanent install
$ claude install-plugin ~/workspace/storytime

# Or per-session
$ claude --plugin-dir ~/workspace/storytime

Every skill invocation echoes storytime v0.3.0 so you know what version you're running.

Your First Session

1. Bootstrap (optional)

/storytime-bootstrap

Creates .storytime/ in your repo. Skip it — the main skill offers to create it on first run.

2. Run It

/storytime "our public API has no rate limiting and we're seeing abuse from scrapers"

Be specific. "Add rate limiting" is vague. "API has no throttling, scrapers are hammering /search at 200 req/s, need per-client limits that respect auth tiers" gives the team something to work with.

3. What Happens

SURVEY — explores your codebase. Presents an artifact inventory if prior specs exist.
ASSEMBLE — proposes 3-7 personas. At least one OPERATOR. You can adjust.
ICEBREAKER — team discusses status quo, grounded in code. Sub-problems identified.
BREAKOUT — parallel deep dives on sub-problems with 2-3 personas each.
POST-BREAKOUT PAUSE — summary cards for each breakout. You proceed, dig in, revise, or add more.
CONVERGE — full team merges findings into a plan. Also available standalone via /storytime-converge.
REVIEW — plan presented to you. Challenge, revise, or approve.

Returning to a Topic

/storytime

Run bare /storytime to see recent threads. Incomplete sessions are highlighted. If only one thread is incomplete, it auto-resumes. Or invoke directly: /storytime rate-limiting.

Automatic Checkpointing

The thread auto-checkpoints after every phase. If your session is interrupted, the next /storytime detects the incomplete thread and offers to resume. No explicit save needed.

Skill Reference

/storytime <problem-statement>

Full workflow. Use for features, architecture decisions, investigations.

/storytime "we need rate limiting on the public API"
/storytime "should we migrate from REST to gRPC for internal services?"

/storytime-breakout <sub-problem>

Focused investigation without the full pipeline.

/storytime-breakout "is Redis or Memcached better for our rate limit counters?"

/storytime-converge <topic>

Merge breakout results into a plan. Use after independent breakouts or to re-converge.

/storytime-converge rate-limiting

/storytime-qa @persona <question>

Query personas about past decisions.

/storytime-qa @noa should we use the same middleware pattern for WebSocket?
/storytime-qa @team does our rate limit decision still hold after the auth refactor?

/storytime-retro <topic>

Reconvene team: plan vs what was built.

/storytime-pr-qa <pr>

Team handles PR review comments with proposed responses.

/storytime-cohort <action>

Manage personas: list, hire, fire, bench, evolve, promote.

/storytime-survey

Standalone codebase survey with artifact inventory and coverage fingerprint.

/storytime-status

Dashboard: cohort, threads, decisions, stale citations.

/storytime-bootstrap

Initialize .storytime/. Storytime-native, adapt-in-place, or export-only.

/storytime-consolidate

Organize, archive, roll up documents, backfill timestamps.

/storytime-absorb

Team reads and discusses existing docs or code.

/storytime-export

Convert output to ADRs, GitHub issues, Linear tickets, Kiro specs.

/storytime-undo

Revert at any granularity: phase, episode, thread, specific file, or redo.

Effort Estimation

Storytime uses Complexity and Scale instead of time estimates.

ComplexityComplexityHuman analog
1Single-file, single-conceptQuick fix
2Few files, one systemStraightforward task
3Multiple files, one systemA morning's work
5Cross-system, multiple ownersSolid day of work
8Architectural, multi-systemMulti-day effort
13Foundational changeSprint-sized (MUST decompose)

Scale (1-5) measures blast radius: 1 (file) → 2 (module) → 3 (service cluster) → 4 (users) → 5 (ecosystem).

Tips

  • Be specific in your problem statement. Context drives quality.
  • Challenge the team during REVIEW. That's what it's for.
  • Use breakouts for focused questions. Don't run the full pipeline for one investigation.
  • Park when you need to think. The thread checkpoints and you resume later.
  • Trust the warm start. The narrative preamble is always fresh.
