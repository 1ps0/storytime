Storytime

A Claude Code plugin that builds technical specifications through structured conversations between domain-expert personas.

$ claude install-plugin ~/workspace/storytime

or per-session: claude --plugin-dir ~/workspace/storytime

How It Works

Describe a problem. Storytime surveys your codebase, assembles a team of domain-expert personas, and runs a structured conversation that produces a plan — grounded in your actual code, with citations, decisions, and visual aids.

  ├── breakout-dsp.md    DSP algorithm deep dive
  └── plan.md            ASCII slide deck + implementation steps

Key Concepts

Personas
Domain-expert lenses, not characters. An OPERATOR asks about kill switches. A SKEPTIC asks "do we need this?" Every claim cites file:line.
Episodes
Sessions are chapters in an ongoing story. Same topic, continuing narrative. Warm start synthesizes a "previously on..." so you pick up without re-reading the book.
Decisions
Append-only, numbered per topic (AGC-001, AGC-002). They cite the code and personas that drove them. Never deleted, only superseded.
Threads
The bookmark (_thread.md). Tracks episodes, team state, open questions, and last git commit. Park mid-session and resume later with full context.

Warm Start

When you revisit a topic, storytime reads the thread state, decision log, persona histories, and git delta, then synthesizes a narrative recap:

What Makes It Different

vs writing specs by hand

Storytime is interactive. The team asks questions you wouldn't have thought of. An OPERATOR asks "what's the kill switch?" before you write code.

vs ADRs

ADRs document decisions after the fact. Storytime generates them as part of the design process, with code citations and persona rationale built in.

vs Kiro / Speckit

Those tools focus on formatting. Storytime focuses on the conversation that produces the spec — investigation, debate, and evidence.

vs just asking Claude

Structured multi-perspective conversation instead of one voice. 3-7 lenses that ground claims in code and build on each other across sessions.

Getting Started

# Install
$ claude install-plugin ~/workspace/storytime

# Initialize storytime in your project
$ /storytime-bootstrap

# Run your first session
$ /storytime "describe your problem here"

# Check status later
$ /storytime-status

# Come back to a topic (warm start)
$ /storytime agc

See HOWTO.md for the full developer guide and PRIMER.md for the value proposition.
